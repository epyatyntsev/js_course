# Заняття 14. Іммутабельність (базове розуміння)

## Коротко про урок

На цьому занятті ви дізнаєтесь, що таке мутація даних, чому пряма зміна об'єктів і масивів може призводити до непередбачуваних помилок, і як уникати цих проблем через створення нових структур.

## Що є в `index.js`

- проблема прямої мутації — що відбувається зі спільними посиланнями
- іммутабельне оновлення об'єктів через spread `{...obj, key: value}`
- іммутабельні операції з масивами: `[...arr, item]`, `filter`, `map`, `slice`
- іммутабельне оновлення елемента масиву через `map` + spread
- патерн стану з history — undo через масив знімків стану

## Що варто запам'ятати

- присвоєння `const b = a` не копіює об'єкт або масив — це друге посилання на той самий об'єкт
- `{...obj, key: value}` — створює новий об'єкт з усіма полями `obj` і оновленим `key`
- `[...arr, item]` — додає елемент без мутації оригінального масиву
- `arr.filter(...)` і `arr.map(...)` завжди повертають новий масив
- іммутабельний стан дозволяє реалізувати undo: зберігай попередній стан у history, відновлюй при скасуванні

## Домашнє завдання

1. Напиши функцію `updateUser(user, changes)`, яка повертає новий об'єкт з оновленими полями, не змінюючи оригінал.
2. Напиши функцію `addItem(arr, item)`, яка повертає новий масив з доданим елементом.
3. Напиши функцію `removeItem(arr, id)`, яка повертає новий масив без елемента з вказаним `id`.
4. Напиши функцію `toggleDone(tasks, id)`, яка повертає новий масив, де задача з вказаним `id` має перемкнутий прапорець `done`.
5. Зроби список нотаток з полем вводу і кнопкою «Додати» — зберігай список іммутабельно (без `push`). Додай кнопку «Скасувати», яка відміняє останню дію.
